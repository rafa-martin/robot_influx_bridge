# Robot Influx Bridge Workspace

This repository contains the ROS 2 packages that connect robot telemetry to InfluxDB using pluginlib-based translators.

## Packages

### `robot_influx_bridge`

The bridge package provides the InfluxDB connector and ROS 2 component that manages:

- Loading translator plugins via `pluginlib`.
- Subscribing to arbitrary ROS 2 topics using generic subscriptions.
- Converting translated line protocol strings into batches written by the `InfluxWriter` helper.
- Configuring mappings via parameters (see `config/robot_influx_bridge.yaml`).

It exposes the `robot_influx_bridge::TranslatorBase` interface which translator plugins must implement. A convenience resolver maps message types to default translator plugins. Custom plugins can be configured per mapping through the `plugin` parameter.

### `robot_influx_common_interfaces`

This package houses reusable translators for common ROS 2 message types:

- `sensor_msgs/msg/Imu`
- `nav_msgs/msg/Odometry`
- `sensor_msgs/msg/BatteryState`

Each translator converts serialized messages into InfluxDB line protocol using shared helpers for escaping and timestamp handling. The package exports its plugin description file so that `robot_influx_bridge` can discover the translators automatically.

## Adding New Translators

1. Create a new package or use an existing one that depends on `robot_influx_bridge`.
2. Implement a class deriving from `robot_influx_bridge::TranslatorBase`.
3. Register the class with `PLUGINLIB_EXPORT_CLASS` and update the package's plugin description XML.
4. Optionally add a default mapping by extending `InfluxBridgeNode::resolvePluginClass`.

## Configuration Overview

Mappings are driven by ROS 2 parameters. A minimal example is provided in `robot_influx_bridge/config/robot_influx_bridge.yaml`:

```yaml
/**:
  ros__parameters:
    influx:
      url: "http://localhost:8086"
      org: "org"
      bucket: "bucket"
      token: "token"

    writer:
      max_batch: 1000
      max_queue: 100000
      flush_ms: 500

    mappings_ids:
      - imu

    imu:
      topic: "/imu"
      type: "sensor_msgs/msg/Imu"
      measurement: "imu"
      plugin: ""  # optional override
```

When the `plugin` field is empty the bridge will select a default translator for known message types. Static tags can be added through the nested mapping parameters generated by `bridge_parameters.yaml`.
